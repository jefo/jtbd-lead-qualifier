# JTBD Lead Qualifier: архитектура

## Задача

Квалифицировать лида на разработку бота до первого разговора: понять задачу, контекст, бюджет и сроки, показать ориентир по цене и отдать менеджеру готовую карточку.

## Сценарий

| Состояние | Что спрашивает | Данные |
| --- | --- | --- |
| `welcome` | приветствие | — |
| `ask_name` | имя | `name` |
| `ask_job` | задача бота, мультивыбор | `job[]` |
| `ask_context` | канал, мультивыбор | `context[]` |
| `ask_struggles` | текущая боль | `struggles` |
| `ask_outcomes` | желаемый результат | `outcomes` |
| `ask_extras` | CRM / аналитика / оплата, мультивыбор | `extras[]` |
| `ask_timeline` | сроки | `timeline` |
| `ask_budget` | бюджет | `budget` |
| `pre_offer` | пре-оффер | `estimate` |
| `ask_examples` | показать примеры? | — |
| `show_examples` | кейс | — |
| `book_call` | телефон | `phone` |
| `booked` | финал | — |
| `nurturing` | финал для «дорого / позже» | — |

## Условный пре-оффер

В `ask_budget` два перехода на одно событие:

1. если `extras` содержит `Интеграция с CRM` — `Бот для SaaS-триала`, `$1500–2500`, `4–6 недель`;
2. иначе — `Бот для вебинарной воронки`, `$800–1200`, `3–4 недели`.

PersonaForge выбирает первый переход, условие которого выполнено. Если ни одно условие не подошло, диалог остаётся на месте.

## Мультивыбор

Кнопки `ADD_JOB`, `ADD_CONTEXT`, `ADD_EXTRA` не меняют состояние, а добавляют значение в массив:

```ts
assign: { job: { op: "add", value: "payload.value" } }
```

Переход «Далее» (`SUBMIT_JOBS`) уже двигает диалог.

## Скоринг

`scoreLead()` — чистая функция. Она не знает про Telegram и не ходит в сеть.

Баллы:

- бюджет: 3 / 2 / 1;
- сроки: 2 / 1;
- CRM: +1;
- оплаты: +1;
- задача про продажи: +1;
- Telegram: +1.

Температура: `>= 5` горячий, `>= 3` тёплый, иначе холодный. Карточка перечисляет причины, чтобы менеджер видел, откуда взялась оценка.

## Слои

```text
src/bot/definition.ts   FSM + ViewMap + форма (данные)
src/scoring/            оценка и карточка (чистые функции)
src/telegram/adapter.ts polling, callback-кнопки, доставка
src/demo.ts             консольный прогон
src/index.ts            composition root
```

Движок — `persona-forge`. Приложение не содержит собственного FSM, формы или рендера.

## Telegram

- `/start` создаёт диалог, если активного нет; если есть — присылает текущий экран.
- Текст вне `/start` уходит событием `text` с `payload.text`; так собираются имя и телефон.
- Кнопки передают `callback_data` вида `EVENT` или `EVENT|{"value":"..."}`.
- После финального состояния карточка лида уходит в `MANAGER_CHAT_ID`.
- Сообщения с ошибкой не меняют состояние; пользователь видит подсказку.

## Ограничения

- In-memory репозитории PersonaForge: диалоги теряются при перезапуске.
- Нет CRM, календаря, оплат и аналитики.
- Скоринг фиксированный, не обучаемый.
- Телефон собирается текстом, без `request_contact` и нормализации.
- Один активный диалог на чат.
- Нет миграций определений и версионирования сценария.
